# Voice architecture (provider-agnostic)

Status: app side and gateway built 2026-10-02 and tested end to end with simulated calls (`tests/voice/e2e-call.test.ts` runs the real gateway over a real WebSocket against the real turn handler). Not deployed, not yet run against a live Twilio call, migration 071 not applied. Provider decision deferred (Steven). Research: `docs/voz-investigacion-2026-10-02.md`.

## Principle

The brain is the existing agent pipeline (`src/lib/agent-runtime/`). Voice is a **channel**, like web and SMS: every caller turn goes through admit (rate limit, budget, opt-out), screen (DLP on the transcript), crisis protocol, tools with their policies (two-phase confirmation, owner approvals), escalation, audit chain and encrypted transcript. Providers only move audio.

```
Caller ── PSTN ── Twilio number
                     │  (A) Twilio ConversationRelay: STT (Deepgram Flux) + TTS (ElevenLabs), interruptions
                     ▼
            voice-gateway (WebSocket, always-on; Fly.io/Railway)   ← this repo: /voice-gateway
                     │  signed HTTPS per turn, streamed text back
                     ▼
   Next.js app: POST /api/agent/{slug}/voice/turn  → runTurn(channel "voice")  → Claude (streaming)

   (B) Vapi / Retell-style "custom LLM": provider calls
       POST /api/agent/{slug}/voice/vapi/chat/completions (OpenAI-compatible SSE) → same runTurn
```

## Contract 1 — gateway → app: voice turn

`POST {APP_URL}/api/agent/{slug}/voice/turn`

Headers:
- `content-type: application/json`
- `x-voice-ts`: unix seconds
- `x-voice-signature`: hex `HMAC_SHA256(key, "${ts}.${rawBody}")`, key = `HKDF-SHA256(VOICE_GATEWAY_SECRET, salt="", info="loucells/voice-gateway/v1", 32 bytes)`. The app rejects missing/invalid signatures and `|now - ts| > 300`. Constant-time compare. If `VOICE_GATEWAY_SECRET` is unset on either side, voice is off (fail closed).

Body:
```json
{
  "slug": "acme-pools",          // must equal the URL slug (the signature covers the body, not the path)
  "callSid": "CA…",              // provider call id (string, ≤ 64)
  "callerVerified": true,        // SHAKEN/STIR attestation A, from the ticket; missing = false
  "from": "+15615550123",       // caller E.164 (may be "anonymous")
  "to": "+15617821310",         // business number called
  "turnId": "uuid",             // unique per turn (idempotency)
  "event": "start" | "utterance" | "dtmf" | "end",
  "text": "final caller utterance (utterance events)",
  "lang": "en" | "es" | null,   // language detected by STT, if any
  "dtmf": "1",                  // dtmf events only
  "interruptedAgentText": "…"   // optional: what the agent had said before the caller cut in
}
```

Response: `200`, `content-type: application/x-ndjson`, one JSON object per line, streamed as produced:
```json
{"type":"text","token":"Claro, "}           // speak this (stream sentence fragments as they come)
{"type":"text","token":"déjame revisar."}
{"type":"language","lang":"es"}             // switch STT/TTS language for the rest of the call
{"type":"handoff","reason":"owner_transfer","target":"+1561…"} // end AI session and transfer the call
{"type":"hangup","reason":"completed"}       // end the call after speaking pending text
{"type":"end_turn"}                          // this turn is complete (last on success; optional after handoff or hangup, which also complete the turn)
{"type":"error","code":"…"}                  // gateway speaks a generic fallback line, keeps the call
```
`event:"start"` returns the welcome line (AI disclosure + Florida recording notice + "How can I help you?") — generated by the app from the agent's config, never by the gateway. `event:"end"` lets the app close the call record (no speech returned). Non-200, an `error` line, the app unreachable, a stream that drops mid-reply, or a timeout (8 s to first byte, 30 s total) → the gateway speaks a fixed fallback in the call language ("Sorry, I'm having trouble. Let me get someone to call you back."). The caller never gets silence.

## Contract 2 — Twilio side (gateway)

- Incoming call webhook (in the app): `POST /api/agent/{slug}/voice/incoming` verifies the Twilio signature and returns TwiML `<Connect action="/api/agent/{slug}/voice/after"><ConversationRelay url="wss://{GATEWAY}/relay" … /></Connect>` with `<Parameter>` elements carrying `slug` and a short-lived signed `ticket`.

**Ticket format (fixed, the app mints exactly this, see `src/lib/voice/auth.ts` `mintTicket` and `voice-gateway/src/crypto.ts`):**
`ticket = base64url(JSON.stringify({slug, callSid, from, to, verified, maxMin, nonce, exp})) + "." + hex(HMAC_SHA256(key, base64urlPayload))`, `nonce` = 12 random bytes hex, `exp` = unix seconds, now + 120 s at most (the gateway allows 10 s of skew). Same HKDF key as the turn signatures. The gateway requires: `slug` = the `slug` custom parameter, `callSid` = the setup message's CallSid, nonce never used before (single use). `from`/`to` come from the Twilio-signed webhook; the gateway uses them, not the setup message's. `verified` = `StirVerstat` starts with `TN-Validation-Passed-A`. `maxMin` = the agent's `max_call_minutes` (the gateway hangs up one minute after it).
- The gateway accepts the WebSocket only with a valid ticket, then maps ConversationRelay messages (`setup`, `prompt`, `interrupt`, `dtmf`, `error`) to Contract 1 and Contract 1 responses back to ConversationRelay messages (`text` tokens with `last`, `language`, `end` with `handoffData`).
- `…/voice/after` (in the app) receives the Twilio action callback when the relay session ends. `HandoffData` is JSON `{reason,target}` (set by the gateway from the `handoff` line). If `reason` is `owner_transfer` or `owner_take_over` AND `target` equals the agent's configured `transfer_number`, it returns `<Dial timeout="20" answerOnBridge="true" action="…/voice/after?stage=dial"><Number>…</Number></Dial>`; the number always comes from config, a different target is ignored. `SessionStatus=failed` (the relay never worked, e.g. the gateway is down) → say that someone will call back, create a `voice_session_failed` callback escalation, hang up. Otherwise `<Hangup/>`. The dial result (`?stage=dial`, `DialCallStatus`): completed → hang up; anything else → say that someone will call back, create the callback escalation, hang up. No `<Record>`: recording needs consent.
- Both Twilio webhooks verify `X-Twilio-Signature` with the workspace's own auth token from the vault (same helpers as SMS). Everything fails closed (voice off, agent not live, no `VOICE_GATEWAY_URL`/`VOICE_GATEWAY_SECRET`, no credentials): a short polite `<Say>` in the agent's language and `<Hangup/>`.

### Gateway behavior the app relies on
- Only final prompts (`last:true`) reach the app. A new utterance aborts the in-flight turn: the gateway closes the fetch, and the app stops (no further model calls or tool runs, nothing recorded for the half turn; `request.signal`).
- Stream that ends without `end_turn` (and without handoff/hangup) or drops mid-reply: the gateway speaks its fallback line. EN "Sorry, I'm having trouble. Let me get someone to call you back." ES "Lo siento, estoy teniendo problemas. Haré que alguien te devuelva la llamada."
- The body has no "previous turn failed" flag. Unresolved: the app does not yet escalate after a gateway-side fallback (idea: a voice_calls turn marker).

## Provider B: Vapi / Retell custom LLM
`POST /api/agent/{slug}/voice/vapi/chat/completions` (Vapi base URL: `…/api/agent/{slug}/voice/vapi`). OpenAI-compatible: request `{messages, stream, call:{id, customer:{number}}}`, response SSE `data: {"object":"chat.completion.chunk","choices":[{"index":0,"delta":{"role":"assistant","content":"…"},"finish_reason":null}]}` … a final chunk with `finish_reason:"stop"` … `data: [DONE]` (a single JSON `chat.completion` when `stream:false`). Vercel compatible, no WebSockets.
- Auth: `Authorization: Bearer <secret>` (or `x-voice-secret`). The app stores only `sha256(secret)` in `integrations.voice.vapi_secret_hash`. Generate in the admin panel (button "Generate custom LLM secret", sent as `vapi_secret_rotate: true`); the secret is shown once. No hash stored = every request is 401 (same answer for unknown agent, voice off or wrong provider).
- Call id: `call.id` (else `metadata.callSid`, else `x-call-id`); 400 without it. Transcript session `call_<id>`.
- Vapi owns the greeting and the transfer: set the assistant first message to the exact `voiceWelcome` text shown in the panel. If the conversation has no assistant message yet, the first reply carries the AI disclosure anyway. Live transfer is not offered on this provider: an escalation is a saved callback plus a spoken line.

## Turn behavior (app)
- Pipeline channel `voice`: admit (spoken opt-out phrases, per-call/agent rate limit) → crisis → pause/budget → DLP → spoken confirmation → model (Haiku, `chat` role, prompt cache, streamed) → record. Model deadline 20 s per turn, 320 max tokens.
- Streaming: text deltas are cut into sentences (first chunk may leave at a comma) and rendered for speech (no markdown, URLs, emojis; prices, times and phone numbers spoken). While a tool runs, the model's own lead-in counts, otherwise one filler ("Claro, déjeme revisar." / "Sure, let me check.").
- Two-phase confirmation by voice: the booking tool only stores the pending action (keyed by the caller's contact, from the caller number); the agent says the action out loud; the caller's whole utterance being yes/sí (and spoken variants: yeah, claro, dale, adelante, perfecto…) executes it on the next turn with no model call, exactly once; no/mejor no drops it. Anonymous callers get no booking tools.
- Opt-out: only explicit spoken phrases ("stop texting me", "no me escriban más", "unsubscribe", "baja"). A bare "stop" is barge-in, not an opt-out. Wins over crisis, confirmation and the model; the call continues.
- Crisis: the fixed safe message (988 / 911) and an alert; the call is NOT transferred for crisis (the line stays open).
- Escalation: with a `transfer_number` and the business open (booking.business_hours in its time zone) the app emits `handoff` (twilio_cr only); otherwise a callback is saved (`escalations` row, channel voice, contact = the caller) and the agent says so. DTMF 0 asks for a person. Owner take-over in the portal: stand-down line, then transfer or hang up.
- Language: the app switches the call (`language` event) when the caller clearly speaks the other language (3+ words, clear majority).
- `max_call_minutes`: past it, a polite wrap-up and `hangup`.
- Idempotent on `turnId`: a retry replays the finished reply (per instance) and the first claim is shared through the rate limiter store; a duplicate in flight answers `end_turn` only.

## Review 2026-10-02: decisions that keep it safe and natural

Security
- **Caller ID can be faked.** Phone numbers are spoofable, so the number alone never unlocks existing appointments. Only a SHAKEN/STIR full attestation ("A": the carrier vouches the caller owns the number) gets `get_my_appointments` / `reschedule_appointment` / `cancel_appointment`. Unverified callers (B, C, failed, absent, and every Vapi call) can ask questions, check times, book a new visit, or get a callback; the prompt tells the agent to offer a callback for existing appointments without saying whether any exist. `voice_calls.caller_verified` records it.
- **Tickets are bound to one call and single use** (callSid + nonce), and the caller's identity travels inside the ticket, so a stolen ticket can't open a second session or claim another number.
- **Turn signatures are bound to the agent** (`slug` in the signed body must match the URL).
- **A confirmation belongs to the conversation that asked for it.** Pending actions carry `origin` (`call_<sid>` / `sms_<contact>`); a "sí" on a call never runs an action proposed by text or on another call, and a texted YES never runs one proposed on a call. Older rows without `origin` are SMS-only.

Reliability
- **No dead air, ever:** app unreachable, dropped stream or timeout → fallback line; relay session failed (gateway down) → `/voice/after` apologizes and files a callback; the 15-minute health cron emails Steven when the gateway's `/health` fails (rule `voice_gateway_down`, 6 h dedupe).
- **Deploys don't hang up on callers:** two always-on Fly machines, rolling deploys, SIGTERM drains (health 503, no new calls, live calls finish, up to 280 s; `kill_timeout = 300`).
- **Silence:** "Are you still there?" after ~10 s of silence (after the agent's words have played), goodbye on a second silence. Hard length cap = `max_call_minutes` + 1.
- **Endings are not clipped:** `end` (transfer, hangup, goodbye) is sent after the last words have had time to play (~14 chars/s + 0.4 s).
- **Barge-in cancels the model call** (AbortSignal from the request), so no tokens are spent on an answer nobody hears.
- **Interruptions keep context:** if the caller cuts in before the answer is stored, their line is kept (user row only) and what they actually heard is placed after it on the next turn.

Latency
- **DLP on calls:** Layer 1 (regex) runs on every utterance. Layer 2 (a model call, ~0.5 to 1 s) runs on calls only when the words could carry high-risk data: a run of 4+ digits, 4+ spoken digits, or words like social / seguro / tarjeta / cuenta / routing / password / contraseña / pin / código. Speech-to-text writes spoken numbers as digits, which Layer 1 catches. Web and SMS keep Layer 2 on every message ≥ 24 chars.
- Contact and call-record lookups run in parallel; the system prompt is cached; Haiku (`chat` role) answers and streams sentence by sentence; Fly `iad` sits next to Vercel `iad1` and Twilio US1.
- Node 22 LTS in the gateway image (Node 20 is past end of life).

Twilio number setup (outside the code)
- Primary voice webhook: `POST https://<app>/api/agent/<slug>/voice/incoming`.
- **Fallback URL** ("Primary handler fails"): a TwiML Bin that forwards to the owner's phone (`<Dial>`), so if the app itself is down the call still reaches a person.

## Instant owner alerts (2026-10-03)

`src/lib/agent-runtime/owner-alert.ts`, called from every escalation (web, SMS, phone, including "transfer not answered" and "relay session failed").
- **Off by default.** Steven turns it on per agent in the admin ("Instant alerts to the owner") and types up to 3 addresses (`integrations.owner_alerts`). On with no address is refused (422). Restorable with config versions.
- **Template**, EN/ES by the portal's language: what to do (call back / reply to the text / follow up the chat), why (fixed label from the escalation reason), **the problem** (one short note: the assistant's escalation summary, or the customer's last words when the assistant couldn't answer, labeled as such), the customer's number only if it is a valid E.164, and a link to the conversation in the portal (login required).
- The note comes from untrusted words, so `ownerNoteText()` strips it of anything a scam needs: DLP masking, links removed, every run of 4+ digits removed (no account numbers, amounts or phone numbers), control characters removed, one line, 200 chars. The footer says Loucells Core never asks for money, codes or passwords by email. A crisis escalation never carries a note (privacy).
- No email during a live transfer (the owner's phone is already ringing); if nobody answers, the callback escalation sends it.
- **10 per hour per workspace** (token bucket); over that, no email and a DENY audit row. Every attempt is audited (`owner_alert:sent|failed:<channel>:<recipient count>`), without addresses or numbers. Steven's internal alert still goes out as before.
- Email only for now (texting the owner needs a registered 10DLC sender).

## Security review 2026-10-03

Scope: everything since b961d61 (voice channel, gateway, portal/admin parity, owner alerts) plus dependencies.

Fixed
- **Next.js 16.2.6 → 16.3.8.** 16.2.6 had critical advisories (RCE in `next/og` ImageResponse, which the site uses for the OG image; RCE in image optimization with AVIF), plus SSRF, DoS and cache-confusion advisories. Production (main) runs the vulnerable version until this deploys. `npm audit --omit=dev`: 0 critical, 0 high (1 moderate, build-time only).
- `shadcn` moved to devDependencies (a CLI; only its CSS is imported at build). Its MCP SDK / hono / ip-address chain is no longer a production dependency.
- **Call summaries now follow retention**: past the workspace window, `voice_calls.summary_cipher` is cleared by the daily purge (call record kept); counted in the purge audit row.
- **One session per call**: a second `start` for an existing call is refused (409) and the gateway hangs that socket up. Closes ticket replay across gateway machines (each machine has its own single-use list).
- Gateway refuses to start unless `APP_URL` is https (transcripts travel on it).

Checked, no change needed
- Spoofed caller ID cannot make the business text a victim: reminders and confirmations need recorded transactional consent (SMS opt-in or the client's app), which a call never grants.
- Toll fraud: the only number ever dialed is the configured transfer number (`/voice/after` ignores any other target); no `<Record>`.
- Twilio signatures on `/incoming` and `/after` (workspace's own token); HMAC + slug binding on `/turn`; Vapi secret hash with constant-time compare and identical 401s; `/api` is outside the locale proxy.
- Cross-tenant: every new query (calls, summaries, minutes, attribution, status) is scoped by workspace; `voice_calls.call_sid` is globally unique but reads/writes are workspace-scoped.
- Portal renders summaries and notes as text; admin-only routes for owner alert addresses; `.env.local` is 600 and git-ignored.

Residual (accepted or pending Steven)
- Connection floods against the gateway (unauthenticated sockets are closed after 10 s; Fly has no WAF). Watch `fly logs`; add per-IP limits if it ever happens.
- Rate limits fall back to per-instance memory without Upstash in Vercel (pending env), so caps are per instance.
- `escalations.summary` (DLP-masked) is not purged by retention (pre-existing).
- Naile Studio's own app (separate repo) is on Next 16.2.4 and needs the same upgrade.
